# 内容准确性审查框架

用于 D2 深度审查的第一个环节。检查应用中的文本内容、数据展示、说明文案是否准确。

---

## 审查维度

### 1. 医学/健康信息准确性（如果应用涉及）

**检查点：**
- [ ] 成长发育参考数据是否来自权威来源（如 WHO）
- [ ] 喂养建议是否符合医学共识
- [ ] 症状或疾病描述是否准确
- [ ] 是否有医学免责声明（如「本应用仅供参考」）
- [ ] 数据版本是否最新（比如 WHO 2006 vs 2024）

**示例问题：**
- ❌ 宝宝体重"第 100%位"——超出正常范围的表述不准确
- ✓ 宝宝体重"第 97%位"——符合医学标准

### 2. 用户指导文案清晰性

**检查点：**
- [ ] 关键功能的说明是否有歧义
- [ ] 按钮文案是否清楚表示会发生什么
- [ ] 错误提示是否说明了原因和解决方案
- [ ] 是否有不当的营销或过度承诺

**示例问题：**
- ❌ 「保存资料」——不清楚是保存到哪里
- ✓ 「保存到云端」——明确说明了目的地

### 3. 数据展示准确性

**检查点：**
- [ ] 数据计算逻辑是否正确（如百分位数计算）
- [ ] 数据聚合是否准确（如周平均值）
- [ ] 时间显示是否一致（「2 小时前」vs「14:30」）
- [ ] 单位是否统一（kg vs g、cm vs m）

**示例问题：**
- ❌ 周数据显示「今天睡了 3.2 小时」——不符合婴儿睡眠规律
- ✓ 周数据显示「今天睡了 7.5 小时」——合理的值

### 4. 功能描述与实现一致性

**检查点：**
- [ ] 功能在 App Store 或应用内描述是否与实现相符
- [ ] 是否承诺了没有实现的功能
- [ ] 是否隐藏或低调呈现的功能实际上有很强的功能
- [ ] 订阅说明是否清楚（包括价格、周期、取消方式）

**示例问题：**
- ❌ 说「支持离线访问」但实际没有
- ✓ 说「在线查看历史数据，离线可查看本地缓存」——准确

### 5. 隐私和免责声明

**检查点：**
- [ ] 是否有隐私政策链接
- [ ] 是否说明了数据的收集、使用、存储方式
- [ ] 是否有医学免责声明（如果涉及健康建议）
- [ ] 用户权限请求的说明是否准确

**示例问题：**
- ❌ 应用请求了「相机权限」但从不使用
- ✓ 应用请求了「相机权限」且在「拍照上传」功能中使用

## 审查工作流

### 第一步：信息收集

需要了解：
1. 应用涉及哪些内容领域？（医学、教育、金融等）
2. 是否有权威数据来源？
3. 数据最后更新是什么时候？
4. 是否有用户反馈过信息不准确？

### 第二步：逐页面审查

逐个检查应用的主要页面和流程，记录：
- 页面名称
- 发现的问题
- 问题等级（关键/重要/次要）
- 建议的修复方案

### 第三步：问题分类

按等级分类：
- **🔴 关键**：会误导用户决策的错误信息
- **🟠 重要**：数据不准确但不影响核心使用
- **🟡 次要**：表述不清但不会造成实际问题

### 第四步：生成问题清单

输出格式：

```
【问题 1】：宝宝成长百分位显示超限
- 位置：宝宝详情 > WHO 生长曲线
- 问题：显示「第 105%位」，超出医学合理范围
- 根本原因：百分位计算算法不符合 WHO 标准
- 建议修复：使用标准 z-score 转换，限制范围在 3-97%
- 优先级：🔴 关键
```

## 审查检查清单

- [ ] 已了解应用的内容领域和数据来源
- [ ] 已逐页检查关键信息准确性
- [ ] 已验证医学/专业信息（如适用）
- [ ] 已检查免责声明和隐私说明
- [ ] 已分类和排序问题
- [ ] 已生成问题清单和建议
