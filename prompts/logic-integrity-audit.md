# 业务逻辑完整性审查框架

检查应用的业务流程、数据流转、边界情况处理是否完整。

---

## 审查维度

### 1. 用户主流程完整性

**检查项：**
- [ ] 用户登录/注册流程是否完整
- [ ] 核心功能流程是否能从开始到结束完成
- [ ] 付费流程是否完整（展示价格 → 支付 → 验证 → 权限开启）
- [ ] 数据保存是否实时生效
- [ ] 用户退出流程是否清晰（登出、删除账户）

**检查方法：** 以真实用户身份完整走一遍流程，记录卡顿点

### 2. 边界情况处理

**空数据情况：**
- [ ] 没有数据时是否显示「暂无数据」而不是崩溃
- [ ] 列表为空时的 UI 是否友好

**网络错误：**
- [ ] 网络断开时是否有清晰提示
- [ ] 离线状态下能否继续使用（如有离线模式）
- [ ] 重连后是否自动重试

**用户未登录：**
- [ ] 需要登录的功能是否有明确提示
- [ ] 是否能跳转到登录页面
- [ ] 登录后是否返回原页面

**异常数据：**
- [ ] 字段超长时是否处理（截断/换行）
- [ ] 特殊字符是否正确展示
- [ ] 极端值（0、负数、超大数值）是否处理

### 3. 数据一致性

**检查项：**
- [ ] A 页面修改的数据，B 页面能否立刻看到
- [ ] 页面刷新后数据是否保持一致
- [ ] 多设备同时修改时是否有冲突处理
- [ ] 删除操作是否同步到所有相关页面

**示例问题：**
- ❌ 在列表页删除了一条记录，详情页仍然显示
- ✓ 删除后列表和详情页同时更新

### 4. 状态转移逻辑

**检查项：**
- [ ] 页面状态转移是否有遗漏（如果状态定义在 CLAUDE.md）
- [ ] loading/success/error 状态是否都有处理
- [ ] 是否会卡在某个中间状态无法自动恢复
- [ ] 返回上一页时状态是否正确恢复

### 5. 权限和访问控制

**检查项：**
- [ ] 付费用户和免费用户的权限边界是否清晰
- [ ] 是否有未授权访问的漏洞
- [ ] 权限变更时（如取消订阅）是否立即生效

---

## 审查工作流

### 步骤 1：定义核心流程

列出应用的主要用户流程：
1. [流程 1]：[目标] → [步骤] → [预期结果]
2. [流程 2]：...

### 步骤 2：流程完整性检查

对每个流程检查：
- [ ] 每一步是否都能完成
- [ ] 是否有卡顿点
- [ ] 是否有错误处理
- [ ] 是否有缺失的步骤

### 步骤 3：边界情况验证

主动测试：
- 网络断开时的行为
- 数据为空时的显示
- 特殊字符输入
- 极端值输入
- 权限相关操作

### 步骤 4：问题分类

```
【问题】：删除操作后列表不更新
- 流程：用户删除记录 → 列表应该刷新
- 实际：列表不变，需要手动刷新
- 根本原因：删除接口没有触发列表重新加载
- 修复方案：删除成功后调用列表刷新接口
- 优先级：🔴 关键（影响核心体验）
```
