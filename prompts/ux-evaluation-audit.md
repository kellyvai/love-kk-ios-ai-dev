# UX 评估审查框架

从真实用户视角评估应用的易用性、流畅度、是否符合用户预期。

---

## 审查维度

### 1. 新用户入门体验

**检查项：**
- [ ] 首次打开应用是否能快速理解功能
- [ ] 是否有清晰的新手引导
- [ ] 核心操作是否直观（是否需要思考）
- [ ] 是否会感到功能过载

**衡量标准：** 一个陌生人打开应用，5 分钟内能否完成一次核心操作

### 2. 核心流程顺畅度

**检查项：**
- [ ] 从打开应用到完成主任务需要几步
- [ ] 是否有不必要的确认对话
- [ ] 点击后是否有即时反馈
- [ ] 是否有长时间的等待（超过 1 秒未反应）

**红旗信号：**
- ❌ 用户需要做超过 5 步才能完成主要操作
- ❌ 点击按钮没有反应，用户不知道发生了什么
- ❌ 页面加载时间超过 3 秒

### 3. 信息架构清晰性

**检查项：**
- [ ] 用户能否快速找到他们需要的功能
- [ ] 导航结构是否符合用户心智模型
- [ ] 页面标题是否清楚表示当前位置
- [ ] 返回方式是否明显

**测试方法：** 问目标用户「如果你想 [操作]，你会在哪里点」

### 4. 错误恢复难度

**检查项：**
- [ ] 用户出错后是否能快速纠正
- [ ] 错误提示是否说明了原因
- [ ] 是否能轻松返回上一步
- [ ] 是否有不可恢复的操作（如删除）

**示例：**
- ❌ 输入错误，重新填写 15 个字段
- ✓ 只需修改错误的字段重新提交

### 5. 视觉和交互一致性

**检查项：**
- [ ] 相同功能的按钮是否有相同的外观
- [ ] 颜色使用是否一致
- [ ] 交互模式是否一致（如点击按钮的反馈）
- [ ] 文案风格是否一致

---

## 审查工作流

### 步骤 1：用户测试

邀请 3-5 个目标用户，记录：
- 他们花了多长时间理解应用
- 他们卡在哪些地方
- 他们的直观反应

### 步骤 2：单独测试核心流程

独立地完成一遍核心操作，记录：
- 需要多少步
- 是否有明确的反馈
- 是否有卡顿感

### 步骤 3：检查常见的 UX 反模式

```
反模式检查清单：
- [ ] 点击后没有视觉反馈（如 loading 状态）
- [ ] 需要在多个页面切换才能完成一个任务
- [ ] 重要信息需要向下滚动才能看到
- [ ] 返回键位置不清晰
- [ ] 文字过小或过多
- [ ] 颜色对比度不足
```

### 步骤 4：问题分类

```
【问题】：用户不清楚数据是否保存成功
- 症状：用户填完资料点「保存」，页面关闭，用户不确定是否成功
- 原因：没有成功提示，直接关闭了
- 改进建议：保存成功后显示绿色 toast「保存成功」，延迟 1 秒再关闭
- 优先级：🟠 重要（影响用户信心）
```

---

## 检查清单

- [ ] 已邀请真实用户进行可用性测试
- [ ] 已独立完成核心操作并计时
- [ ] 已检查所有常见反模式
- [ ] 已评估新用户入门体验
- [ ] 已验证信息架构清晰性
- [ ] 已生成问题清单和优先级
